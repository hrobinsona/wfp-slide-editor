# BRIEF v2.12 — Adaptive inspector: never hide the element you're editing

Design 7 from the Ink Glass handoff bundle (`7-adaptive-inspector.html`,
README §"Design 7"), plus a **smart overlap gate** specified directly by
Harry: the inspector only fades when it actually covers the selection.

## Problem

The docked inspector sits top-right and overlaps whatever you select there.
Today the user must manually minimise the panel to see a top-right element
while moving/resizing/retyping it (the v2-2 resize spec literally minimises
the inspector to reach the SE handle). The panel should get out of the way
by itself during any live edit.

## One rule

Any live manipulation dissolves the inspector to a whisper
(`.wfpe-inspector[data-fade="true"]` → `opacity: 0.16`, pointer-events kept)
and pins a lit coral value tag (`.wfpe-scrub-tag`) to the selection. Chrome
restores ~380ms after the gesture ends. The **toolbar never fades**.

## Smart overlap gate (Harry's addition — not in the handoff)

Fade only when the selection's bounding box intersects the inspector's
rectangle:

```js
function rectsOverlap(a, b) {
  return a.right > b.left && a.left < b.right && a.bottom > b.top && a.top < b.bottom;
}
```

- The check runs **per gesture** at gesture start.
- During drag-move (and resize) it **re-tests on every move**: fade the
  moment the element passes under the panel, un-fade when it leaves.
- The check uses the inspector's *live* rect — a minimised inspector is just
  its 36px header, so a selection under the folded body area doesn't fade it.
- When the inspector dock is closed (no selection / multi-select) the gate is
  always false.
- The **value tag shows either way** — it's useful feedback regardless of
  overlap.

## Triggers → tag content

| Trigger | Fade on | Fade off | Tag |
|---|---|---|---|
| Scrub FONT value (drag L/R on the field) | first move past deadzone | pointerup | `N px` |
| FONT ± steppers | on click | 380ms timer | `N px` |
| Drag-move element | drag start (past deadzone) | drop | `X n  Y n` (slide px) |
| Resize (handles) | drag start | drop | `W × H` (slide px) |
| Inline text edit | startTextEdit (re-test on each `input`) | endTextEdit | none |
| OPACITY slider | `input` | 380ms timer after drag end | `N %` |
| Weight / Align seg click | on commit (no-op clicks don't fade) | 380ms timer | `Bold` / `Center` etc. |

Weight/Align are an extension of the handoff table (Harry named weight
explicitly); their tag shows the chosen label rather than a number.

While `state.editingText` is open, the restore timer keeps the panel faded
(tag still hides) — typing bursts don't flicker the chrome. Restore happens
at endTextEdit.

## FONT becomes a scrubbable value field

- The font field (`[data-wfpe-row="font-size"] .wfpe-inspector-field`) gets
  `cursor: ew-resize` / `touch-action: none`. Drag left/right changes size
  ~1px per 3px dragged (`round(dx / 3)`), clamped at `FONT_SIZE_MIN_PX`
  (no max — decks legitimately use >96px display sizes; deviation from the
  reference's 96 cap).
- A plain click (pointerup with no move past a 3px deadzone) focuses the
  input and selects its text — typing an exact value + Enter/blur commit is
  unchanged. While the input is focused, pointerdowns are left native so
  in-field text selection still works.
- ± steppers unchanged.
- History: one scrub gesture = one entry (`startInspectorTxn` on first move,
  `endInspectorTxn` on pointerup) — same contract as the opacity slider drag.

## Value tag vs dimension bubble

The coral tag supersedes the v2.2 dim bubble *during gestures only*: while
the tag is visible the bubble is display-suppressed, but its `textContent`
keeps updating (v2-2-position-size.spec asserts text deltas across a resize
without asserting mid-gesture visibility). The bubble returns when the tag
hides. No change to bubble behaviour outside gestures.

## Implementation shape

- New fragment `src/editor/85-adaptive-fade.js` (added to `PARTS` in
  `scripts/build-editor.mjs`): overlap gate, `liveEditUpdate(tagText)` /
  `liveEditEnd()` / `liveEditBlip(tagText)` state machine, restore timer,
  font-scrub pointer wiring.
- Tag element created in `30-ui-inspector-controls.js` next to the dim
  bubble; CSS in `20-dom-css.js` (coral gradient per reference, scoped under
  `#${ROOT_ID}`, `position: fixed`, pointer-events: none, hidden in
  overview alongside the other selection chrome).
- `[data-fade="true"]` rule placed after `[data-suppressed="true"]` so fade
  (0.16) wins over the export-menu dim (0.55) if both ever apply.
- Call-site wiring: `80` onMouseMove/onMouseUp + onResizeMove/onResizeUp,
  `90` startTextEdit/endTextEdit (+ transient `input` listener),
  `60` nudgeFontSizeWithHistory, `30` opacity slider input / seg commit.
- Everything stays inside `#wfp-editor-root`; no new attributes on user
  elements → export scrubbing is unaffected.

## Out of scope

- Keyboard ArrowUp/Down font nudge fade (not in the handoff table; can join
  the blip family later).
- Annotation dot restyle (design 6b) — separate brief.
- Colour picker fade — the native picker dialog overlaps arbitrarily;
  deferred.
