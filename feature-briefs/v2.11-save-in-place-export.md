## Context

The download-based export creates a loop tax when iterating with an agent: edit in browser → Cmd+S downloads `deck-edited.html` to `~/Downloads` → manually move/re-upload it so the agent sees it → repeat. v2.6 replaces the destination, not the pipeline: **Export's primary action writes straight over the source file on disk** via the File System Access API, so the agent sees each save immediately.

**Verified feasibility (2026-07-23):** on `file://` pages in Chrome, `isSecureContext` is true and `showSaveFilePicker` / `showOpenFilePicker` / IndexedDB are all available (probed in real Chromium via Playwright). A standalone demo of the full flow — first-save picker, silent subsequent writes, IndexedDB handle persistence across reload with one-click re-grant — was validated by Harry in real Chrome. Chrome's security floor: the first save per deck always costs one save-dialog interaction (a page can never silently acquire write access to a disk path); each page reload costs one "allow changes" click via the remembered handle. That is the minimum friction any browser allows.

## Decisions baked in

1. **One Export button.** The separate Handoff toolbar button is removed. Export gains a count badge showing the number of agent annotations; badge hidden at zero. (Mockup 4b shows the badge treatment.)
2. **Click Export → two-row action menu** (4b pattern), recommended action first:
   - **Row 1 — save in place (recommended, `↵`):**
     - With ≥1 annotation: label "Annotated handoff", sublabel "Includes N agent notes". Writes the *handoff* HTML (existing `buildHandoffExportHtml` pipeline, metadata included) over the bound file.
     - With 0 annotations: label "Save", sublabel "Edits only". Writes the *clean* HTML (existing `buildExportHtml` pipeline) over the bound file. Row 1 is therefore never disabled — the zero-annotation state degrades to a plain save, unlike the old always-disabled Handoff button.
   - **Row 2 — clean copy (download):** label "Clean copy", sublabel "Edits only — notes stripped". Exactly today's `exportHTML()`: downloads `<original-name>-edited.html`. Unchanged in all browsers.
3. **Cmd/Ctrl+S is a macro for Row 1** — same action, no popup. Both existing capture-phase Cmd+S sites (the `state.editingText` branch and the normal branch) route to the row-1 action instead of `exportHTML()`. While the menu is open: `Enter` triggers row 1, `Escape` / click-away closes.
4. **Save-in-place mechanism (Chromium):**
   - No handle bound yet → `showSaveFilePicker({ suggestedName: <original basename from location.pathname> , types: [html] })`. The user typically re-selects the source file (overwrite) but may pick a new name — that is the intentional free "save as branch"; whatever they pick becomes the bound file.
   - Handle bound → `queryPermission({mode:'readwrite'})`; if not granted, `requestPermission(...)` (one-click re-grant — legal because save is always user-gesture-initiated); then `createWritable()` → write → `close()`.
   - Handle persisted to IndexedDB (DB `wfp-editor`, store `handles`, key `location.href`) so a page reload needs only the re-grant click, not a new dialog. On load, look up the handle so the first save after reload skips the picker.
   - Picker cancelled (`AbortError`) → no write, no state change, quiet toast ("Save cancelled").
   - Write failure (handle stale — file moved/deleted, `NotFoundError` etc.) → drop the bound handle (memory + IndexedDB) and immediately re-open the picker in the same gesture; if that is also cancelled, toast the failure.
5. **Fallback (no `showSaveFilePicker` — Safari/Firefox):** row 1 keeps its content semantics but downloads instead — annotated → `<name>-agent-handoff.html`, zero-annotation → `<name>-edited.html` (exactly the v2.5 behaviours). Sublabels in the menu say "Downloads" in this mode so the destination is never a surprise. Feature-detect once at init.
6. **Toasts name the real file:** "Saved deck.html", "Saved deck.html — 3 agent notes", "Exported clean copy". Use `handle.name`, not a derived name — the user may have branched at the picker.
7. **Content invariants unchanged.** Both write paths reuse the existing clean/handoff serialization pipelines untouched: no editor chrome, no `data-wfp-edit-*`, handoff metadata only on the annotated path. Nothing about IndexedDB or handles appears in the document — storage lives in the browser, not the DOM, so there is no new export-leak surface. Normal save after a handoff reimport must still strip stale handoff metadata (existing rule, now exercised by the row-1 zero-annotation path).
8. **REQUIREMENTS.md, DESIGN.md, ROADMAP.md updated** as part of this work: Export section rewritten for the action menu + in-place destination; toolbar control list drops Handoff; DESIGN.md documents the handle lifecycle; ROADMAP marks this delivered.

## What to build — phases

### Phase 1 — Toolbar merge + action menu (build-first TDD)

Merge Handoff into Export: one button, annotation-count badge (live-updating; hidden at zero), popup menu per 4b adapted to the existing toolbar dialect. Menu keyboard behaviour (`Enter`, `Escape`, click-away), row labels switching on annotation count. **Row actions temporarily call the existing download functions** (`exportHandoffHTML` / `exportHTML`) so Phase 1 is shippable without the FSA engine. Cmd+S routes through the row-1 dispatcher from day one. Playwright coverage: menu open/close, badge count, label states, Enter/Escape, Cmd+S dispatch, no menu artifacts in exported HTML.

### Phase 2 — Save-in-place engine (strict TDD)

The FSA flow from Decision 4, behind a small module boundary (e.g. `acquireHandle` / `writeToHandle` / `forgetHandle` + IndexedDB helpers). Native pickers cannot be driven by Playwright, so tests stub `window.showSaveFilePicker` via `addInitScript` with a fake handle that records written content into the page (pattern below); assert: picker called with the right `suggestedName`, silent second save, permission re-grant path, cancel path, stale-handle recovery, fallback mode when the stub is absent, and that written HTML byte-equals the corresponding download pipeline's output.

```js
// test stub sketch
await page.addInitScript(() => {
  window.__written = [];
  window.showSaveFilePicker = async (opts) => ({
    name: (opts && opts.suggestedName) || 'stub.html',
    queryPermission: async () => 'granted',
    requestPermission: async () => 'granted',
    createWritable: async () => ({
      write: async (data) => { window.__written.push(String(data)); },
      close: async () => {},
    }),
  });
});
```

Note: the stubbed handle is not structured-cloneable, so IndexedDB persistence needs its own test treatment (either assert the put/get calls against a spied store, or tolerate storage failure gracefully in-code — storage failure must never block the save itself).

## Gotchas for the builder

- Both Cmd+S interception sites must be rerouted; miss one and the old download ghost returns in text-edit mode.
- `showSaveFilePicker` must be reached while transient user activation is still valid — call it directly in the click/keydown turn, before any unrelated `await`s.
- The picker's initial directory cannot be controlled from `file://` (only `suggestedName` can); Chrome opens the last-used save location. Do not chase `startIn`.
- `queryPermission`/`requestPermission` may be missing on some handle implementations — guard with feature checks, treat absence as granted-after-write-attempt.
- The in-app preview/browser panes load local files as snapshots — manual verification of the real picker flow must happen in actual Chrome, matching the TDD mode: build-first phases end with a real-browser pass.
