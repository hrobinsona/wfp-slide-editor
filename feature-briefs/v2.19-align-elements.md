# v2.19 — Align Elements

**Status:** planned
**TDD mode:** strict (pure geometry logic; write the spec first, confirm it fails, then implement)
**Depends on:** v2.18 (multi-select inspector — the Align row lives in the multi-mode surface)

## Goal

With two or more elements selected, align them along an edge or axis: an **Align** row in the inspector (multi mode only) with six buttons — align Left, Center (horizontal), Right, Top, Middle (vertical), Bottom.

## Product decisions

- **Reference frame:** the **selection bounding box** (union of member rects). Align Left moves every member so its left edge equals the bbox's left edge; Center-H centers each member on the bbox's horizontal midline; etc. This is the standard design-tool behaviour for ≥2 elements. No align-to-slide (out of scope).
- **Placement:** a new `wfpe-inspector-row` labelled "Align", shown **only** when `data-multi="true"` (CSS-gated like v2.18's row gating). Six icon buttons in the row (`dataset.align = 'left' | 'center-h' | 'right' | 'top' | 'middle-v' | 'bottom'`), each with a `title`. Icons: simple SVG glyphs matching the existing `ICONS` style (bar + two boxes, standard align iconography).
- **Movement semantics:** alignment is a positional move — exactly what drag does. Each moved member must be absolutely positioned first: reuse the **same unlock path drag and inspector X/Y use** (`unlockToAbsolute`, which also pins flex/grid siblings so the promotion doesn't reflow). Do not invent a second unlock mechanism.
- **Scale correctness (critical):** rects from `getBoundingClientRect()` are viewport px; style writes are slide px. Compute per-member deltas in viewport space, then divide by `getCanvasScale()` before writing styles — same as drag (`80-drag-resize-unlock.js:185-187`) and the local-rect helper (`80-drag-resize-unlock.js:270-275`). Apply the delta to the member's current offset (`offsetLeft`/`offsetTop` or parsed `left`/`top` — match how drag computes its write targets).
- **History:** one click = one txn = one entry covering every moved member; single undo restores all positions AND any unlock side-effects (the txn snapshot machinery already covers pins/markers — same guarantee drag has).
- **No-op guard:** members already at the target coordinate (within 0.5 slide-px) are skipped; if nothing would move, return before opening a txn — no history entry, no unlock side-effects.
- **Sizing unchanged:** align never resizes. W/H untouched.

## Non-goals

- Distribute (equal spacing) — natural follow-up, not now; note in ROADMAP if desired.
- Align-to-slide / align single element.
- Smart/spacing guides during drag.

## Implementation sketch

1. `40-helpers-selection-inspector.js` (or nearest fitting spot per surrounding style): `computeAlignPlan(mode, members)` → `[{ el, dxView, dyView }]` in viewport px from member rects + selection bbox; pure and unit-cheap to test through Playwright. Then `applyAlignPlan(plan)`: for each entry — `touchElement`, unlock-to-absolute if needed, convert by scale, write `left`/`top`.
2. `30-ui-inspector-controls.js`: build the Align row + six buttons next to the other rows; one delegated click handler: guard (≥2 members, non-empty plan) → txn → apply → `endInspectorTxn` → `refreshSelection()`.
3. `20-dom-css.js`: row hidden unless `[data-multi="true"]`; button styling consistent with existing icon buttons.
4. Build fragments → `npm run build:editor` before each test run.

## Test plan — `tests/v2-19-align-elements.spec.js`

Fixture: `fixtures/foreign-deck.html`. The fixture's deck has no CSS transform scale — so ALSO cover the scaled case: one test injects a `transform: scale(0.8)` on the deck root (in-page, editor loaded after) and asserts alignment still lands correctly; the drag suite may already have a pattern for this — check `tests/04-drag.spec.js` and reuse it if present.

1. Align Left on 3 absolutely-positioned members → all left edges equal the original bbox left within 0.5px; tops unchanged.
2. Align Center-H → member horizontal centers equal within 0.5px; Align Bottom → bottom edges equal.
3. Static (flow) member: gets unlocked via the same path drag uses (assert absolute positioning + no sibling reflow explosion — model the assertion on existing unlock tests) and aligns correctly.
4. Scaled deck (per above): align Right with scale applied lands all right edges equal in viewport space within 1px.
5. One history entry per click: align, then single undo restores every member's rect (and any unlock side-effects); redo re-aligns.
6. No-op: clicking Align Left twice — second click adds no history entry (undo depth proves it).
7. Export cleanliness after align: styles survive, no editor markers.
8. Row visibility: Align row absent/hidden for single selection, visible for multi.

## Gotchas

- **Deck scale division** — the #1 critical gotcha from CLAUDE.md; every viewport→slide conversion divides by `getCanvasScale()`.
- Unlock touches selected elements, siblings, containers — undo must not leave `state.selected`/`selectedElements` detached; the existing txn machinery covers it, but assert selection survives undo in the spec.
- One txn per click; `touchElement` every member (and anything unlock pins) inside it — unlock's own code already handles its pinned siblings; do not double-wrap.
- Fragments only; rebuild before tests; export must stay marker-free.
