# v2.18 — Multi-select Inspector

**Status:** planned
**TDD mode:** strict (behaviour matrix + history/export logic; write the spec first, confirm it fails, then implement)
**Depends on:** v2.17 (Front button ships multi-target logic with no UI surface)

## Goal

Show the inspector when more than one element is selected, with a reduced control surface, so set-wide edits become possible: multi bring-to-front, multi font-size, multi opacity/colour. This is a **deliberate behaviour change** — today `refreshInspector()` hides the dock unless exactly one element is selected.

## Product decisions

- **Visibility:** the dock is visible whenever `getSelectedElements().length >= 1`. When `> 1`, the dock gets `data-multi="true"` (on `inspectorDock`) and CSS gates rows off that attribute — no per-row JS show/hide where an attribute selector will do.
- **Control surface in multi mode:**
  - **Enabled:** font size (input + ± steppers), opacity (input + slider), colour rows (text colour + background), action row: **Front** and **Reset**.
  - **Disabled (visible but inert, with explanatory `title`):** Duplicate, Delete. Their underlying functions already no-op on multi-selection; give them `disabled` + styling so the UI stops lying about it. Enabling them for multi is out of scope.
  - **Hidden:** X/Y/W/H geometry rows (per-element values, ambiguous for a set), annotation row (already gated to single), any text-edit affordance.
- **Header label:** the inspector header that names the selected element should read "N elements" in multi mode (check how the single-selection label is populated and extend it).
- **Mixed values:** when members disagree, the field shows empty with placeholder `Mixed`; when all agree, show the shared value. The opacity slider tracks the primary (`state.selected`) value when mixed.
- **Write semantics:**
  - Typing an absolute value (font size, opacity) applies that absolute value to **every** member.
  - Font ± steppers apply a **relative** step to each member from its own current computed value (so a 12px and an 18px caption both grow by the stepper increment, preserving hierarchy). This matches design-tool conventions.
  - Colour swatches apply the chosen colour to every member.
  - Font size only applies to members that pass `isTextBearing`; non-text members are skipped silently.
- **History:** one gesture = one txn = one history entry covering all touched members (`startInspectorTxn()` → `touchElement(each)` → writes → `endInspectorTxn(ctx)`). A single undo restores all members.
- **No-op guards** stay per-member (skip members already at the target value); if no member changes, no entry (endTxn's `snapshotsEqual` already guarantees the entry side; still guard the writes to avoid pointless style churn).
- **Front button:** already multi-capable (v2.17 forward-compat). Update the forward-compat comment on `computeFrontZIndexPlan` (now `computeFrontPlan`; see v2.17.1) (the path is now reachable) and convert the v2.17 multi-select test from `dispatchEvent('click')` to a real Playwright click.
- **Dock positioning:** `positionInspectorStack()` currently bails for `length !== 1`. Extend it to use the multi-selection bounding rect (`getLiveSelectionRect()` already aggregates member rects — verify) so avoidance works in multi mode too.

## Non-goals

- Multi duplicate/delete/copy-paste (functions keep their no-op guards).
- Multi X/Y/W/H editing, multi text edit, multi annotation.
- Alignment tools (that's v2.19, which builds on this).
- Persisting mixed-value editing subtleties beyond the `Mixed` placeholder.

## Implementation sketch

1. `40-helpers-selection-inspector.js`:
   - `refreshInspector()`: `visible = length >= 1`; set `data-multi` on the dock.
   - `positionInspectorStack()`: drop the `length !== 1` bail; use the aggregate selection rect.
   - The inspector repopulate path (`refreshInspectorContent` or equivalent — find it): in multi mode populate shared-or-`Mixed` values for font size/opacity/colour and skip geometry rows.
   - `applyInspectorChange(prop, next)`: for `fontSize`/`opacity` iterate `getSelectedElements()` inside ONE txn; leave `x/y/w/h` single-element (rows hidden in multi, but keep the guard defensive).
   - Colour application site (find where swatches write) gets the same iteration.
2. `30-ui-inspector-controls.js`: stepper handlers pass a "relative step" intent for multi (per-member step), typed input keeps absolute semantics; Duplicate/Delete get `disabled` wiring driven by selection state (update wherever gating is refreshed — `applyModeFeatureGating` or the repopulate path).
3. `20-dom-css.js`: `[data-multi="true"]` row gating (hide geometry rows), disabled action-button styling.
4. Build: fragments only, then `npm run build:editor` before every test run.

## Existing-test impact (deliberate changes only)

`tests/v2-multi-select.spec.js` (and possibly others) may assert the inspector is hidden or `data-visible="false"` under multi-selection. Update those assertions to the new contract — but ONLY assertions about inspector visibility/reachability. Any other failure is a regression, not a contract change. List every existing-test change in the report with justification.

## Test plan — `tests/v2-18-multi-select-inspector.spec.js`

Fixture: `fixtures/foreign-deck.html` (private fixtures are absent on this machine). Model setup on v2.17's spec.

1. Inspector visible with 2 elements selected; `data-multi="true"`; geometry rows hidden; annotation row hidden; Duplicate/Delete disabled; header reads "2 elements".
2. Single selection still shows the full surface (`data-multi="false"`, geometry rows visible) — regression guard.
3. Font `+` stepper on two text elements with different sizes: both step by the increment (hierarchy preserved), ONE history entry, one undo restores both.
4. Typed font size: both members end at the same absolute value; non-text member (if selectable) is untouched.
5. Opacity write applies to all members in one entry; mixed values show `Mixed` placeholder on repopulate.
6. Front via REAL click on a multi-selection raises all members above an unselected overlapping sibling, preserving relative order (this replaces/upgrades the v2.17 dispatchEvent test).
7. Reset with multi-selection restores every edited member in one entry.
8. Export cleanliness after multi edits: no `data-wfp-edit-*`, `contenteditable`, editor root; the written styles survive.

## Gotchas

- `editor.js` is generated — fragments only, rebuild before tests.
- One txn per gesture; `touchElement` before EVERY member write, inside the txn.
- Undo/redo must not leave `state.selected`/`state.selectedElements` pointing at detached DOM (no DOM moves here, but Reset restores attribute state — verify selection survives).
- Editor keys stay capture-phase; no new document-level key handlers.
- Do not alter single-selection behaviour except where this brief says so.
