# v2.21 — Agent Notes Panel

**Status:** planned
**TDD mode:** build-first (visual dock surface; implement, verify in browser, then Playwright before completion)
**Depends on:** v2.5 (agent annotations), v2.11 (stack/dock architecture)

## Goal

A browsable panel listing every agent annotation across the whole deck — not just pins on the active slide — with click-to-jump and prev/next "flicking". Inspired by the comment rail in [petergyang/human-review](https://github.com/petergyang/human-review): before handing a deck to the agent, the user can review the full queue of notes, jump to any of them, and cycle through them in order.

## Product decisions

- **Placement:** a new `.wfpe-notes-dock` grid-fold segment in the existing `.wfpe-stack`, between the export dock and the inspector dock. Same 246px width, 380ms `grid-template-rows` fold, `data-visible` mechanics as the other docks. NOT a separate side rail — the inspector opens *below* the list, so cards don't shift when selection changes.
- **Toggle:** a new "Agent notes" toolbar button (speech-bubble icon) between Overview and Export, with a count badge cloned from the export badge (hidden at zero). Opening the panel closes the export menu and vice versa — one middle segment at a time.
- **Cards:** one button-row per annotation, in slide order (document order of `getAnnotatedElements`): slide-number chip, ellipsized target snippet (`summarizeTargetText`), 2-line-clamped instruction, status strip (amber `needs-input`, slate `skipped`, matching marker colors), agent reply line when present. The card for the currently selected element carries `data-active="true"`.
- **Jump:** clicking a card resolves the element by annotation id at click time, exits overview / enables edit mode as needed, activates the target slide via the `navigateToSlide` pattern (`state.deckMutated` + `synchronizeSlideState` — robust against stale fixture nav closures), selects the element, and opens its note in the inspector. Focus does NOT move into the note textarea (a focused textarea would swallow the next `N` keystroke).
- **Flicking:** prev/next chevrons in the panel header plus `N` (next) / `Shift+N` (previous), wrapping around. Cursor resumes from the last-jumped note (`state.notesCursorId`) when nothing is selected. First `N` press opens the panel if closed. Keys consumed capture-phase with `preventDefault` + `stopPropagation`, only when at least one annotation exists and no typing target is focused.
- **Dismissal:** the panel is a browsing surface, not a menu — it does NOT close on click-away (unlike the export menu). It closes via the toolbar toggle, its header close button, or Escape (after the deselect step in the Escape onion: menu → text edit → overview → deselect → notes panel).
- **Re-render triggers:** `refreshExportUi()` (covers save/delete/undo/redo/slide-delete/live-refresh/startup) plus `setEditMode`/`setOverviewMode`. The panel renders lazily — no card DOM is built while it is closed. It does NOT hook `refreshAnnotationMarkers()` (per-scroll tick).
- **Mode-agnostic:** the panel stays open and populated in overview mode and with edit mode off; jumps normalize mode themselves.

## Non-goals (this pass)

- Deck-level (unanchored) note — remains the ROADMAP "Slide- and Deck-scoped Agent Notes" candidate.
- Edits-list ("Your edits") in the panel.
- Orphan detection — annotations live on the element, so they cannot orphan; deleted elements drop their notes.
- Text-range annotations, hidden agent prompts (still REQUIREMENTS non-goals).

## Implementation shape

1. `10-state.js`: `notesPanelOpen`, `notesCursorId`.
2. `20-dom-css.js`: `.wfpe-notes-dock/-inner/-panel/-header/-list/-card/-empty/-badge` next to the dock CSS block; list capped `max-height: 40vh; overflow-y: auto`.
3. `30-ui-inspector-controls.js`: toolbar button + badge, dock DOM as middle stack segment, open/close/toggle beside the export-menu functions, `refreshStackSeams()` four-way extension, click wiring.
4. New fragment `src/editor/45-notes-panel.js` (registered in `scripts/build-editor.js` PARTS): `collectNotesPanelEntries()`, `renderNotesPanel()`, `jumpToAnnotation(id)`, `cycleAnnotation(delta)`. Plain hoisted functions; no evaluation-time cross-fragment calls.
5. Hooks: `refreshExportUi()` badge + render; `setEditMode`/`setOverviewMode` render; `positionInspectorStack()` height sum includes the notes dock.
6. `60-modes-overview-keyboard.js`: `N`/`Shift+N` branch, Escape onion extension.

## Test plan — `tests/v2-21-notes-panel.spec.js`

Fixture: `fixtures/foreign-deck.html` (public). Assertions: toggle + badge tracking; slide-ordered cards with correct chips/snippets/instructions; status/reply rendering; cross-slide jump (active slide, inspector, populated textarea, selected marker); `N`/`Shift+N` flicking with wraparound and typing-guard regression; delete/undo reactivity; export leakage (no `wfpe-notes`, marker regex clean); post-jump ArrowRight advances from the jumped-to slide.

Regression surface: `v2-0-toolbar`, `v2-10-ink-glass`, `v2-12-adaptive-inspector`, `v2-agent-annotations`.

## Accepted limitations

- On short windows, toolbar + export menu + notes list + inspector can approach viewport height; the 40vh list cap plus the inspector's existing `calc(100vh - 72px)` cap mitigate but don't formally solve stacking overflow.
- Card list rebuilds wholesale per fan-out (`replaceChildren`) — fine at annotation counts a human writes by hand. The rebuild also drops keyboard focus from a focused card; the flicking flow is N/Shift+N or mouse, so Tab-into-cards is not a supported path this pass.
