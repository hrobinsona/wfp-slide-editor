# v2.24 — Entrance animations in Overview

**Status:** built, tests green (branch `fix/overview-entrance-reveals`)
**TDD mode:** strict — rendering state and mode lifecycle, verified by computed style
**Depends on:** v2.23 (active-class token resolution), Overview mode

## Problem

Overview renders a grid of every slide, but on a deck that gates its entrance
animations on the active slide only one thumbnail has content. The rest are
blank rectangles.

```css
.reveal                  { opacity: 0; transform: translateY(18px); }
.slide.is-active .reveal { opacity: 1; transform: translateY(0); }
```

Overview's CSS forces `opacity: 1 !important` on each `.slide`, but that
reaches the slide box only — not its descendants. Exactly one slide is ever
active, so every `.reveal` on every other slide stays at `opacity: 0`.
Measured on the real deck: slide 1's reveals compute to `1`, slides 2–20 to
`0`. What stays visible on a few thumbnails is the content that happens not to
be reveal-gated.

## Why this never showed up before

The WFP template opts out of its own entrance rules when it sees the editor's
overview marker (`fixtures/Townhall-1.html:334`):

```css
:is(body[data-deck-static], body[data-wfp-edit-overview="on"]) .reveal,
:is(body[data-deck-static], body[data-wfp-edit-overview="on"]) .stagger > * { … }
```

That is a convention some decks follow, not a contract. The editor has been
depending on deck cooperation for something it should handle itself, so a deck
from any other generator gets a broken overview.

## Two rejected approaches

**Enumerate the animation class names** (`.reveal`, `.table-row`, `.moment`,
`.bar`, `.beat`, …) and force them visible. Only re-breaks on the next
generator, and it would flatten deliberate opacity/transform on slide content.

**Lend the deck's own active class to every slide** so its own rules fire. This
was built and tested, and it works on a deck that ignores its own classes — but
it is actively dangerous on the decks that cooperate best. Townhall's
`observeDeck()` (`fixtures/Townhall-1.html:1781`) watches for externally-moved
`.active` so the deck stays in sync with the editor:

```js
if (el.classList.contains('active') && !el.classList.contains('visible')) {
  this.activate(el);          // and activate() deactivates the previous slide
}
```

Stamping N slides therefore drives the host's navigation N times, leaving the
*last* stamped slide active and the real one deactivated. Ten existing overview
tests caught it. The lesson is worth keeping: **overview must not touch slide
classes at all.**

## Fix

Read the deck's own entrance rules out of its own stylesheets and re-emit them
scoped to overview. Nothing in the DOM changes, so no host observer fires, and
the editor still needs to know nothing about what the deck calls its animated
elements.

On entering overview, walk `document.styleSheets` (skipping the editor's own,
and any that throws on `cssRules` — a cross-origin sheet degrades to the
previous behaviour). A selector qualifies on three tests, each of which exists
because the first cut got it wrong:

1. **It carries the resolved active-class token as a whole class name**, at
   paren/bracket depth zero and outside any string. Raw substring matching
   turned `.slide.is-active-alt .x` into `.slide-alt .x`, and mangled
   `[data-file$=".active"]` into an odd number of quotes.
2. **It has a descendant part.** `.slide.is-active .reveal` yes;
   `.slide.is-active { z-index: 1 }` no — that styles the slide box, which
   overview already governs, and re-scoping it would tell every slide it is
   active.
3. **The gated thing is actually a slide** — the prefix up to and including the
   token is checked with `slide.matches()`. Without this, every `X.active Y`
   UI-state rule qualifies: nav tabs, accordions, progress steps, and (measured
   on the primaries) Townhall's `.agenda-item.active .agenda-num`, which would
   paint every agenda row as selected. Before this check the rewriter emitted
   three false positives and *zero* entrance rules on the installed decks.

The token is then dropped and `body[data-wfp-edit-overview="on"]` prefixed,
which also lifts specificity above the original so the rewrite wins. Selector
lists are split on top-level commas only — splitting inside `:is(a, b)` strands
an unclosed paren, and one malformed prelude makes the parser swallow every
rule after it, which silently disabled the whole feature on exactly the
`:is()` idiom the WFP template uses.

Rules are inserted one at a time through `insertRule` inside `try/catch`, so a
selector this rewriter mishandles is dropped alone rather than voiding the
sheet. `@media` and `@supports` are recursed into and re-wrapped by *type*, not
by the presence of `conditionText` — `CSSContainerRule` has one too, and
re-emitting an `@container` query as `@media` changes what it means. `@layer`
and `@scope` are recursed into without re-wrapping.

Clearing is by `deleteRule`, not by emptying `textContent`: the rules are
inserted through the CSSOM, and setting `textContent` on an element whose text
is already empty is not a mutation, so nothing reparses and every rule stays
live.

Measured result — real deck: 21 entrance rules emitted, nothing left hidden.
Townhall, boilerplate and d2-intelligence-layer: zero rules emitted, which is
correct, because those decks already opt out for themselves.

## Tests

`tests/v2-24-overview-entrance-css.spec.js` is table-driven over the selector
shapes, because the whole feature is string surgery: plain descendant, child
combinator, a comma inside `:is()`, a rule following a tricky one, `@media`
preserved (both matching and non-matching), `@supports`, no-descendant rules
left alone, a non-slide `X.is-active Y` rule left alone, a longer class name not
matched, the token inside `:not()`, a token inside an attribute value,
declaration fidelity (`!important` + custom properties), and a deck of pure
false-positive candidates emitting nothing.

`tests/v2-23-host-deck-compat.spec.js` covers the behaviour end to end on
`fixtures/pointer-nav-deck.html`, which gains the third real-deck trait —
reveal-gated content and no `body[data-wfp-edit-overview]` opt-out:

1. Reveal-gated content is visible on **every** thumbnail.
2. Leaving overview restores the gating and leaves zero injected rules. (This
   assertion is what caught the `textContent` clearing bug.)
3. **Overview mutates no slide class** — a `MutationObserver` across the whole
   enter/exit cycle, not a before/after sample, because the rejected approach's
   failure was transient.
4. A thumbnail click still activates the slide that was clicked.
5. An export taken while overview is open starts on the first slide and carries
   none of the injected CSS.

## Out of scope

- Decks that gate entrance on something other than a class on the slide — a
  scroll observer, an explicit JS `.play()`. Re-scoping CSS cannot reach those.
- Cross-origin stylesheets, which cannot be read at all.
- Native CSS nesting. A nested rule's selector is relative to `&`, which has
  no meaning once lifted out of its parent, so a style rule's children are not
  visited.
- `@import`ed stylesheets. `CSSImportRule` exposes `.styleSheet`, not
  `.cssRules`, and imported sheets are not in `document.styleSheets`.
  Irrelevant for the single-file decks this editor targets.
- **A deliberate later override loses to the rewrite inside overview.** The
  re-scoped rule carries one element more than the original, so a deck rule
  that overrode its own entrance rule at equal specificity is out-ranked in
  overview only. Wrapping the scope in `:where()` would fix that but costs a
  class, which would then lose to any hiding rule more specific than a bare
  `.reveal` — the far more common shape. Winning the base case matters more
  than the override case, so the specificity boost stays.
- Removing the WFP template's own opt-out rule. Now redundant but harmless, and
  editing deck templates is not this change's business.
