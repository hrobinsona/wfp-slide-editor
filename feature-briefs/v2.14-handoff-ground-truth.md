# v2.14 — Handoff Ground Truth: Edit Ledger and Measurements

Implements the "Handoff Ground Truth" roadmap candidate. Manual edits
currently reach the agent as anonymous inline styles — indistinguishable
from authored markup. Two costs: the user cannot propagate a demonstrated
edit ("make slides 3, 4, 6, 10 match what I did here"), and manual edits
are unprotected when an agent regenerates a slide to satisfy a note.
Separately, agents must mentally render raw HTML to answer spatial
questions the editor can measure for free.

## What ships

Handoff exports (the pipeline that runs when at least one agent note
exists) gain two additive payload sections. Clean exports are untouched.

### 1. Edit ledger — `edits: [...]` in the handoff payload

One entry per user-touched element whose inline style differs from its
pristine pre-edit value:

```json
{
  "id": "edit-…",
  "tag": "h1",
  "slideIndex": 2,
  "targetText": "first 240 chars of text content",
  "before": "left: 120px; top: 80px;",
  "after": "left: 90px; top: 64px; width: 640px;",
  "mechanical": false,
  "box": { "left": 90, "top": 64, "width": 640, "height": 207 },
  "computed": { "fontSize": "64px", "fontWeight": "800", "color": "rgb(23, 32, 42)", "backgroundColor": "rgba(0, 0, 0, 0)", "position": "absolute" },
  "overflow": false
}
```

- `before` is the element's pristine inline `style` at its first committed
  change (`state.originalStyles`; `null` when it had none), `after` is the
  current inline `style`. Elements whose before equals after (edited then
  fully undone) are skipped, as are disconnected elements and anything
  inside `#wfp-editor-root`.
- `mechanical: true` marks entries whose element carries
  `data-wfp-edit-frozen` or `data-wfp-edit-flex-frozen` at build time —
  unlock/freeze pinning written by the editor, not user intent. The
  guidance tells agents these preserve layout and are not requests.
- The matching element in the exported file carries
  `data-wfp-agent-edit-id` so entries are deterministically anchored,
  exactly like annotation targets.

**Tracking:** `state.originalStyles` is a WeakMap and cannot be
enumerated, so `endTxn()` also records every changed element in a new
iterable `state.editedElements` (a `Set`). The ledger is computed at
handoff-build time from that set.

**Live-DOM cleanliness:** `data-wfp-agent-edit-id` is stamped on the live
elements only transiently — stamp, `cloneNode`, unstamp, all synchronous
inside the handoff build — so the live document never retains it. Tests
assert zero occurrences in the live DOM after a save.

**Out of scope for the ledger v1:** slide reorder/insert/delete intent
(the file already shows final order; net-order diffing needs an
order-at-boot snapshot — roadmap follow-up if wanted), and text-content
before/after (text originals are not retained outside capped history).

### 2. Measurements on annotations

Each `annotations[]` entry gains the same `box`, `computed`, and
`overflow` fields, measured from the live element at build time.

- `box` is slide-relative and scale-normalized via the existing
  `getSlideBox()` helper (values rounded to 1 decimal).
- `computed` is a fixed small set: `fontSize`, `fontWeight`, `color`,
  `backgroundColor`, `position`.
- `overflow` is true when the element's content overflows its own box
  (`scrollWidth/Height` exceeding `clientWidth/Height` by >1px) or its
  rect escapes its parent's rect by >1px on any edge.

### 3. Guidance

`payload.guidance` and `HANDOFF_COMMENT_TEXT` gain one sentence each:
entries in `edits` are the user's intentional manual changes — preserve
them unless an annotation explicitly asks otherwise; `mechanical` entries
are editor-written layout pinning. Keep the existing subordination clause
and results-contract wording; the ledger is context, never instructions.

### 4. Hygiene

- `removeHandoffArtifacts()` also strips `data-wfp-agent-edit-id` attrs
  (covers reimport of agent-processed files that left them behind).
- Reimport ignores `edits` entirely — the ledger is agent-facing context,
  not restorable state.
- Both export pipelines must produce files free of any live-DOM ledger
  residue; the payload block itself appears only in handoff exports.
- Payload stays `version: 1` — the additions are purely additive and
  omitted-field-tolerant for downstream readers.

## Non-goals

- Slide-order intent diffing (see above).
- Any UI. This release has no visible surface beyond the payload; the
  "propagate what I did here" workflow is exercised through note text
  referencing the ledger, which agents receive automatically.
- Ledger in clean exports or in saves with zero notes (the handoff
  pipeline is the only carrier).
- Restoring ledger state on reimport.

## TDD mode

**strict** throughout — this is export/payload logic with no visual
surface. Every behaviour lands as a failing Playwright test first, in
`tests/v2-14-handoff-ground-truth.spec.js`, harness-based on
`fixtures/foreign-deck.html` with the v2.13 FSA stub pattern (see
`tests/v2-13-live-roundtrip.spec.js`).

Required coverage, each red before green:

1. A committed inspector/keyboard edit (e.g. font-size nudge) plus a note,
   then Cmd+S: payload `edits` has the element with correct
   `before`/`after`, `mechanical: false`, populated `box`/`computed`, and
   a `data-wfp-agent-edit-id` on the element in the written file matching
   the entry id.
2. Annotation entries carry `box`, `computed`, and `overflow` (assert an
   overflow:false case; overflow:true via an element style forced small
   around overflowing content in-page before save).
3. Live DOM after save contains zero `data-wfp-agent-edit-id`; an
   edit-then-undo element produces no ledger entry; the clean-copy export
   contains neither ledger entries nor edit ids.
4. Flow-unlock drag in the fixture's `.chip-row` (flex): pinned siblings
   appear with `mechanical: true`, the dragged chip with
   `mechanical: false` (drag pattern per `tests/04b-flex-freeze.spec.js`).
5. Reimporting a handoff file that still contains `edits` and edit-id
   attrs strips the attrs from the live DOM at boot and re-imports notes
   normally.

## Gotchas for the implementer

- `editor.js` is generated — edit fragments, run `npm run build:editor`,
  never edit `editor.js` directly. `npm run check:editor` must pass.
- Fragment concatenation shares one IIFE: top-level code in earlier
  fragments runs before later fragments' `let`/`const` initializers
  (temporal dead zone). Session-long mutable state belongs on `state`
  (see `state.agentResultsSummary` for precedent). Function declarations
  hoist and are safe.
- Pointer deltas are viewport pixels; slide coordinates need the deck
  scale — `getSlideBox()` already normalizes, use it rather than raw
  `getBoundingClientRect()` for `box`.
- Measurements must be taken from the LIVE document (the clone is never
  laid out); anchor results into the clone via the transient stamp.
- The generic `data-wfp-edit*` strip in `stripEditorArtifactsFromDocument`
  does NOT cover `data-wfp-agent-*` attrs — the handoff pipeline
  deliberately re-adds agent attrs after cleanup. Order of operations in
  `buildHandoffExportHtml` matters; mirror how annotation targets are
  handled.
- Run only the relevant specs while iterating
  (`v2-14-handoff-ground-truth`, then `v2-13-live-roundtrip`,
  `spike-live-refresh`, `v2-agent-annotations`, `v2.11-save-in-place`,
  `08-export` if runnable). The full private-fixture suite cannot run on
  this machine; 4 native-deck tests in `v2-4-modes` and 1 stale badge-size
  assertion in `v2-agent-annotations` fail pre-existing — do not chase
  them.
